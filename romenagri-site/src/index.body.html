Devanagari through programs

Romenagri carries Hindi and Sanskrit text through three layers: Unicode Devanagari, an 8-bit encoding called ACII, and plain ASCII letters, which programs, shell tools and sed scripts can handle. It is the transliteration system under Hindawi, whose language styles are built on it. Its sources are the Romenagri/ directory of the hindawiai/chintamani repository.

Unicode —uni2acii→ ACII —acii2rmn→ Romenagri —rmn2acii→ ACII —acii2uni→ Unicode

Try it

The box runs romenagri.js, a port of the four converters whose tables are generated from the headers of Romenagri/. It is not the production C code: build_site.py --check compares it with the compiled C programs and with the Python models of the tests. Every stage of the chain is shown, so that each can be inspected.

The nukta layer in a paragraph

Unicode has eleven letters with a nukta that are one code point each: {{u:0929,0931,0934,0958,0959,095A,095B,095C,095D,095E,095F}}. ACII writes every one of them as two bytes, the consonant and the nukta (E9). Only two of the eleven had a byte of their own in the table; for the other nine uni2acii wrote the low byte of the code point, so that the cluster {{u:095C,094D,0935}}, typed with the single code point U+095C, came back as {{u:0935}} alone. The layer that the third patch adds has three parts, which are kept apart: a rule (a letter with a nukta is a consonant and a nukta, always), a form (whether the Unicode end writes such a letter as one code point or as two: asis, the default, nfc or nfd, the user's choice) and a warning (off unless asked for) for the characters that have no ACII byte.

How the pages were made

The tables on these pages are read from unicode.h, acii.h, aciihin.h and nukta.h, and every output shown (the bytes, the Romenagri, the crashes, the warning) was written by the compiled C programs when romenagri-site/build_site.py built the site. Nothing in a table was typed in. Documents says how to rebuild and check it.
