The danda

{{danda_note}}

What the code does with the two dandas today, from runs of the compiled programs. The first three columns are the chain; the last says whether the text came back as it went in.

{{danda_table}}
  • The single danda (U+0964) has the ISCII byte EA. The decoder writes | for it, and the lexical layer of rmn2acii never hands | to the parser: it copies it as the ASCII byte 7C, which acii2uni reads as U+007C. In the repository's own corpus, {{u:091A,094B,0932,093E,0964}} comes back as {{u:091A,094B,0932,093E}}|. The danda is outside the round-trip contract.
  • The double danda (U+0965) was written as its low byte 65, the letter e, before patch 0001, so that {{u:091A,094B,0932,093E,0965}} came back as {{u:091A,094B,0932,093E}}e. Patch 0001 gave it the byte 87 and the string _vd, and it round-trips.
  • Nothing in this package retires or changes either of them. What the note says is to be done is for the author to decide. The row of the single danda (EA, |) is in the original tables; the row of the double danda (87, _vd) was added by patch 0001.

The eight cases of the nukta layer

Each case is a place where the layer, or the standard that it follows, asked for a decision or left a limit. A row says “all three” when the three forms give the same line, and otherwise has a row of its own for the forms that differ. Every code point is written out. The ACII column is what uni2acii wrote, the Romenagri column what acii2rmn made of it, and the last column what acii2uni wrote after rmn2acii had turned the Romenagri back into bytes.

The fifteen reserved keys

Fifteen keys that the parser can ask for have no row in acii.h. When the parser asks for a missing key, lookup() returns NULL and the next strcat crashes. They are two things of different kinds. Thirteen are the Latin letter v typed after a consonant stem: v is not a letter of Romenagri ({{u:0935}} is w), and the one spelling in which the parser accepts it is that of {{u:0933}}, lvra, so every other stem followed by v asks for a key that no script has. Two are conjuncts typed as aspirates: Devanagari has no letter for an aspirated l or an aspirated {{u:0931}}, and Hindi and Marathi write those sounds as {{u:0932,094D,0939}} and {{u:0931,094D,0939}}; Romenagri's own spelling is l_ha and _rr_ha, but lh is what a person at a keyboard types.

The author is working on these himself, and nothing in this package changes them. The table shows what the compiled rmn2acii did with each typed form when the site was built. The nukta layer does not touch them either: {{u:0931,094D,0939}} and {{u:0932,094D,0939}} have always passed through the chain from Unicode (case C8).

What is open

Decided on 8 November and closed: the form is a user option and the default is what the converters always wrote (C1, C4); the rule is uniform, a character and a nukta, and is applied before anything is bound (C1, C2, C6); {{u:0934}} takes no byte of its own and D3 is not assigned (C7); the clusters get no special cases (C6, C8); a mixed encoding is not repaired, only reported, on request (C5); no decision on a nukta after a halant (C3); the fifteen reserved keys are not touched (C8).

Left to the reader:

  1. The form for a pipeline. The default is asis. A pipeline that compares or stores text in NFC sets nfc on both converters (ROMENAGRI_NUKTA_FORM=nfc does it for a whole script); one that wants every nukta letter as a pair sets nfd.
  2. Reordering. Folding a nukta that follows a halant needs a decision between a nukta and ISCII's soft halant, which is written E8 E9 as well. The converters do not make it.
  3. A fourth form, all eleven letters as single code points, is a table row and a few lines away. Any normaliser would split the eight again.
  4. The converters as functions. The conversion loops are in the main of each program. nukta_set_form() and nukta_options() give a program that includes nukta.h the form and the options; calling the loops themselves as functions would mean moving them out of main, which the patch does not do.
  5. The low-byte fallback for everything else. A code point that has no row is written as its low byte, which ACII reads as another character (the table below). The cure is to deal with such characters before uni2acii; the warning layer shows which ones there are.
